# Goal 12A isolated industrial boiler, electric pump and desh motor regression

Run `python -B -X utf8 tools/migration/verify_goal12a.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal12a/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles (in each of the two worlds). javac receives its file lists through argument files in the run folder.

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Lines starting with `info:` report observed numbers; they are not asserted and are no gameplay claim. Sections 1t, 4, 9 and 10t are text checks run by `verify_goal12a.py` itself and report the same way. The machine world writes the four new anvil entries (its own `describe` format) to `machine-out/anvil-goal12a.txt` in the run folder; section 9 reads the desh motor line from there.

`python -B -X utf8 tools/migration/goal12a_mutation_check.py` reverts or breaks 10 Goal 12A decisions one at a time (the boiler's proxy above the core removed; the boiler's EXTRA back to `.fluid().heatSource()`; the removal scan back to -2..2 x -1..5 x -2..2; `destroyBoiler` falling back to `pos` without a core; `GROUND_HEIGHT` 71; the first-layer full-solid test removed; the ground threshold `>` instead of `>=`; an operation of -500 HE / +5,000 mB; `getConPos` turned with the facing; `SolderingRecipes.readRecipe` adding the recipe again) in a temporary copy of `src/main/java` under `build/migration/goal12a` and reruns the regression (log: `build/migration/goal12a/mutation_check.log`, one folder per run under `build/migration/goal12a/mutation-runs/`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error. `src/main/java` is hashed before and after; the check fails if it changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere.

`python -B -X utf8 tools/migration/verify_goal12a_resources.py [--source-only]` checks the generated tree against `build/migration/goal12a/stamp-before-g12a.json` (byte for byte the stamp of `e476f5c1`; 3850 files before, 3858 now: exactly the 8 Goal 12A files added, `en_us.json` and `#minecraft:mineable/pickaxe` modified, nothing removed), that the current stamp's inputs match the sources and differ from the pre-Goal 12A stamp in exactly the 24 Goal 12A inputs (17 changed and 3 new Java sources, `zh_cn.json`, the 3 imported assets; the same set as `git diff`/untracked files under `src/main`), the English delta (+6 keys exactly), the pickaxe tag (+`hbmsntm:pump_electric` exactly), the added files, `zh_cn.json` (+6 keys with the expected Chinese, nothing else changed; the pre-Goal 12A bytes by `git show e476f5c1:`), `zh_cn-map.json` (+6 entries: 3 upstream with the original keys, 3 local with a reason; 108 deferred keys unchanged) and the 3 assets against the original files and their SHA-256. Full mode also compares `build/libs/hbmsntm-198A.jar` with the generated files, `zh_cn.json`, the assets and the classes of the 20 changed or new sources, checks the class literals the older scripts use (`GOAL12A_LITERALS`) and writes `build/migration/goal12a/generated-check.json` for `package_goal12a.py`, which keeps the JAR as `build/migration/releases/goal12a/hbmsntm-198A-goal12a.jar` with `SHA256SUMS.txt` and `release.json`, explains every entry of the delta to the Goal 11D release and checks the recorded hashes of the 11D, 11C, 11B, 11A, 10C, 10B, 10A, 9B, 9A and 8 releases. Its helpers `post_goal11d_bytes`, `post_goal11d_generated`, `post_goal11d_tree`, `post_goal11d_input`, `post_goal11d_stamp`, `same_as_post_goal11d` and `goal12a_delta(check)` are imported by the older resource scripts (11D, 11C, 11B, 11A, 10C) to read the post-Goal 11D state; this module imports none of them.

Goal 12B (`build/migration/goal12b/production.diff`) changes the generated tree, the languages and 67 inputs after Goal 12A: `verify_goal12a_resources.py` runs its checks against the post-Goal 12A state read from `verify_goal12b_resources.py` (the pre-Goal 12B stamp, the tree without the Goal 12B additions and with the `3687da34` bytes of the files it changes or retires, the `3687da34` bytes of the Goal 12B inputs, `zh_cn.json` and `zh_cn-map.json`; the git set of the Goal 12A inputs is read between `e476f5c1` and `3687da34`), reads the JAR through `post_goal12a_archive` and runs `goal12b_delta()` (3 more checks); its helpers for the older scripts read the same state, and `goal12a_delta()` ends with `goal12b_delta()`.

`anvil_block.py` holds the exact Goal 12A source block of `AnvilRecipes` and its `WireDenseItem` import; section 1t and the Goal 9A, 9B and 10B resource scripts require both once where Goal 12A put them and remove them (`without_goal12a`) before their unchanged comparisons.

Expected numbers come from the original (`Hbm-s-Nuclear-Tech-GIT`, checked out at `d7ef2df`), not from the NEO classes: `AnvilRecipes.java:215-217` (desh motor: 1 motor, 2 any plastic ingots, 2 desh ingots, 1 gold dense wire, tier 3), `:253-260` (pump: 8 stone bricks, 16 steel plates, 4 lead pipes, 2 motors, 4 vacuum tubes, tier 3), `:399-404` (industrial boiler: 8 steel cast plates, 8 copper ingots, 4 any plastic ingots, tier 3); `CraftingManager.java:174` (PCP / DMD / PCP); `OreDictManager.java:305, 664` (any plastic: polymer and bakelite ingots); `MachineHeatBoilerIndustrial.java:37-42` (EXTRA is `TileEntityProxyCombo().fluid()`), `:78-97` (proxies at the core's four neighbours and four above the core), `:100-120` (first look line: the heat), `:122-125` (standard info); `RenderIndustrialBoiler.java:18-29` (translate only); `TileEntityMachinePumpBase.java:75-94` (tick), `:111-133` (ground check), `:136-140` (sync); `TileEntityMachinePumpElectric.java:12, 16, 20-23, 32-40`; `TilePortShapes.java:101-108` (flare ports); `SolderingRecipes.java:308` and `:353-364`; `Fluids.java:626-627, 634` and `TileEntitySteamEngine.java:47` (200 TU per mB of water, 100 mB of steam per mB, 170 HE per 100 mB of steam). NEO decisions from `migration/GOAL12A.md` (A1 no NBT, A3 `ntm:ingots_plastic`, A4 one entry per copper item, A6 the valid ground blocks, D2g/D2h, D3 Y <= 70) are taken as given.

## Stand-ins

`goal12a_regression/stubs.py` extends the Goal 11C machine world:

- registry entries `NtmBlockEntityTypes.PUMP_ELECTRIC` and `NtmBlocks.WASTE_EARTH` as a real block (as Goal 11A made `DIRT_DEAD`, `DIRT_OILY`); the vanilla blocks the sources and the fixture name (`COARSE_DIRT`, `PODZOL`, `MYCELIUM`, `GLASS`, `SMOOTH_STONE_SLAB`), `SoundEvents.GENERIC_SPLASH`, `BlockPos.north/south/east/west`;
- `BlockState.isRedstoneConductor`: a stand-in of the Minecraft 1.21.1 rule read from the NeoForge sources (`build/moddev/artifacts/neoforge-21.1.228-sources.jar`): `BlockBehaviour.Properties.isRedstoneConductor` defaults to `isCollisionShapeFullBlock` (`BlockBehaviour.java:1079`), `Blocks.GLASS` (`Blocks.java:686-699`) and the leaves (`Blocks.java:7715-7730`) set it to `Blocks::never`, and a slab's collision shape is not a full block. The stand-in answers true for every solid, non-fluid block that is not air and not marked as a non-conductor (glass, oak leaves, smooth stone slab, tuff brick slab). Real collision shapes are not modelled; whether every NEO valid ground block (`waste_earth`, `dirt_dead`, `dirt_oily`) is a full cube in the game is not checked here;
- `Level.dimensionType()` returning a `DimensionType` record with the fixture's `hasSkyLight` (1.21.1's `DimensionType` is a record with that component; no other dimension property is modelled);
- the client hook `NuclearTechMod.proxy.playLocalSound` (recorded), `Component.empty()` and `withColor`, `BobMathUtil.format` with the production body, `ItemInteractionResult` and `Block.useItemOn` (compile-only), `ILookOverlay.printGeneric` recording its title and lines;
- `LoadedBaseBlockEntity.saveAdditional`/`loadAdditional` with the production bodies (muffled, tilted; the super calls removed) instead of the earlier no-ops.

In the fixture, a generator stand-in (`Generator`: adds a fixed HE per tick and offers it to one cable) and an HE sink (`Sink`: subscribes to one cable) are block entities of the fixture, not production classes. The chain's heat source is the production `HeaterOvenBlockEntity` under the boiler core, but it is not ticked: the fixture sets its heat to 10,100 TU before every boiler tick (constant heat, as the Goal 11C chain kept its oven at `MAX_HEAT`), so the oven's fuel, its own pull from below and its decay are not modelled. The steam engine is a bare core block entity (no multiblock, no proxies), as in the Goal 9B/10C chains. Not modelled: rendering, the rotor animation beyond the client tick counter, sound playback, the boiler's identifier use (`useItemOn` is compiled, not run), the multiblock `checkRequirement` and item handling of `setPlacedBy`, real chunk saving (the save round trip calls `saveAdditional`/`loadAdditional` directly), packets (`networkPackNT` is counted, the buffer is the stand-in value list), the dedicated server, other mods.
