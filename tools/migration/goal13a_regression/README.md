# Goal 13A isolated blueprint, alt..circuit, heater and concrete regression

Run `python -B -X utf8 tools/migration/verify_goal13a.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal13a/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles (in each of the three worlds). javac receives its file lists through argument files in the run folder. `--only shredder|recipe|machine` runs one Java world for development (and always ends in a failed "partial run" exit).

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Lines starting with `info:` report observed numbers; they are not asserted and are no gameplay claim. Sections 1t, 3p, 4j, 5, 6t, 7t, 8t and 13t are text/JSON checks run by `verify_goal13a.py` itself and report the same way.

`python -B -X utf8 tools/migration/goal13a_mutation_check.py` breaks 20 Goal 13A decisions one at a time (the blueprint copy not using paper; secret blueprints copyable; the booklet draw skipping the last pool; the booklet used up with no pool; the chest grid 5000 -> 4000; the 50% draw removed; the height draw `nextInt(2)` -> `nextInt(1)`; the chest loot weight 10 -> 9; the meteorite rolls 1-3 -> 1-2; the `!enable528` test inverted; the assembler no longer dropping a pooled recipe without its blueprint; the electric heater default setting back to 1; the `useUpHeat` guard removed; the hum volume 0.25 -> 0.5; the heat exchanging heater tanks back to NONE; the heat exchanging heater anvil copper 16 -> 8; a member dropped from `ntm:any_concrete`; the concrete strength 15 -> 5; the shredder's limestone yield 4 -> 3; `chem.concreteasbestos` back to the sand block) in a temporary copy of `src/main/java` under `build/migration/goal13a` and reruns the regression (log: `build/migration/goal13a/mutation_check.log`, one folder per run under `build/migration/goal13a/mutation-runs/`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error. `src/main/java` is hashed before and after; the check fails if it changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere. The datagen providers and `NtmBlocks` are not compiled: the chest loot weight, the meteorite rolls, the `any_concrete` member and the concrete strength mutations are detected through the text of the mutated copy that sections 4j, 5 and 8t read (the generated JSON cannot change in a source copy); the other mutations are in compiled sources.

`python -B -X utf8 tools/migration/verify_goal13a_resources.py [--source-only]` checks the generated tree against `build/migration/goal13a/stamp-before-g13a.json` (byte for byte the stamp of `12f38317`; 3906 files before, 3927 now = 3906 + 21: exactly the 21 Goal 13A files added, `en_us.json`, `sounds.json` and the meteorite treasure loot table modified, nothing removed), that the current stamp's inputs match the sources and differ from the pre-Goal 13A stamp in exactly the 35 Goal 13A inputs (23 changed and 3 new Java sources, `zh_cn.json`, 8 imported assets; the same set as `git diff`/untracked files under `src/main`), the English delta (+8 keys exactly), `sounds.json` (+`block.electric_hum`), the meteorite table (the 12f38317 table once the appended booklet entry and the uniform rolls are taken out), `zh_cn.json` (+8 keys with the expected Chinese; the pre-Goal 13A bytes by `git show 12f38317:`), `zh_cn-map.json` (+8 entries: 4 upstream with the original keys and both `.lang` files, 4 local with a reason, the two heater descriptions recording the original text; 108 deferred keys unchanged) and the 8 imported assets against the original files and their SHA-256. Full mode also compares `build/libs/hbmsntm-198A.jar` with the generated files, `zh_cn.json`, the assets and the classes of the 26 changed or new sources, checks one class literal for each (`GOAL13A_LITERALS`; `None` where the change adds no string: the class must then differ from the Goal 12B release) and writes `build/migration/goal13a/generated-check.json` for `package_goal13a.py`, which keeps the JAR as `build/migration/releases/goal13a/hbmsntm-198A-goal13a.jar` with `SHA256SUMS.txt` and `release.json`, explains every entry of the delta to the Goal 12B release and checks the recorded hashes of the 12B, 12A, 11D, 11C, 11B, 11A, 10C, 10B, 10A, 9B, 9A and 8 releases. Its helpers `post_goal12b_bytes`, `post_goal12b_tree`, `post_goal12b_generated`, `post_goal12b_input`, `post_goal12b_stamp`, `same_as_post_goal12b`, `without_goal13a_keys`, `post_goal12b_archive` and `goal13a_delta(check)` are the Goal 12B scripts' counterpart for the post-Goal 12B state; no older script imports them yet (see below); this module imports none of the older ones.

Expected numbers come from the original (`Hbm-s-Nuclear-Tech-GIT`, checked out at `d7ef2df`), not from the NEO classes; section 13t requires every transcribed line where it is cited: `ItemBlueprints.java:45-56` (icon by prefix), `:68-101` (the copy), `:105-129` (hover), `:131-144` (pool key); `ItemBlueprintFolder.java:23-26, 44-46, 48-71`; `HbmWorldGen.java:474, 477-499`; `ItemPoolsSingle.java:112, 118-120`; `BlockMeteoriteTreasure.java:24-29`; `TileEntityHeaterElectric.java:31, 61, 70-88, 94, 151-159, 161-166, 173-184, 197-199`; `TileEntityHeaterHeatex.java:42-43`; `AnvilRecipes.java:291-306`; `AssemblyMachineRecipes.java:126, 137-142`; `ChemicalPlantRecipes.java:140-158`; `PowderRecipes.java:36`; `CraftingManager.java:362-365`; `ShredderRecipes.java:153-154, 175, 210`; `OreDictManager.java:501`; `ModBlocks.java:1495-1499`; `sounds.json:57`; the four `en_US.lang` texts of the upstream keys. ## Reading the numbers

The observed numbers are the production code's, not gameplay claims: the 301 ticks of `ass.factorioChip` are the double sum of 300 steps of `1/300` (the original's module accumulates the same way); 99 -> 103 anvil entries and 181 -> 185 shredder entries are the counts of the stand-in worlds' production tables at `12f38317` and now.

## Older suites

Goal 13A moves several things the older suites assert (see the report): their stand-in worlds do not declare what `BlueprintsItem`/`AssemblyMachineRecipes` now call (`InteractionResultHolder.consume/success`, `Player.getAbilities`, `GenericRecipes.pooledBlueprints`, `NtmConfig.enable528`), their anvil, shredder and assembler comparisons count entries, and their resource scripts compare the generated tree with the state after their own goal.
