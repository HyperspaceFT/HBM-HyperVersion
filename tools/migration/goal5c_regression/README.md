# Goal 5C isolated fluid-container regression

Run `python -B tools/migration/verify_goal5c.py` with the existing Python and JDK 21. The script compiles and executes unmodified production `FluidTank`, `FluidContainerRegistry`, `FluidContainer`, `FluidLoaderStandard`, `FluidLoadingHandler`, `MetaHelper`, the heater firebox, combination oven and recipe, wood burner, fluid identifier, and oven menu. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal5c/regression/<id>/result.log`.

The harness models Minecraft's `Level`, inventory, `ItemStack` component map, NBT and byte buffer services. The component model supports the fields and operations used by these production paths; it is not a full Mojang component codec. The fluid registry uses modeled fluid identities and traits, while executing the real container registration and transfer code. The chosen traits are checked against `Fluids.java`: `DEATH` has `LEADCON`, `SPENTSTEAM` and `PLASMA_DT` have `NOCON`, and `LAVA` is hot but has no standard-container temperature gate. It does not execute `Fluids.initialize()` or load the Minecraft registries. Nonstandard fillable-item and infinite-fluid loaders are inert stubs; their transfer behavior is outside this result. Client screens, actual inventory interaction, world saves, gameplay, networking and dedicated-server loading are untested.

The integrated oven run starts with an uncharged firebox and oven and produces ten coke and 1000 mB creosote from ten coal without injecting heat or progress. It fills a named fluid tank, tests oven inventory persistence, removes it from the oven output, and transfers that same tank into a real wood burner configured through `FluidIDMultiItem.receiveControl`. Before inserting it, the burner ticks to apply the selected fluid and its real `canPlaceItem` gate accepts the filled tank. The burner is off while it unloads, marks dirty, and saves and loads its received fluid, empty tank and identifier. A subsequent coal completes after the first drain. The oven's real `canPlaceItem` gate accepts the wood burner's actual returned empty tank; reusing it while processing nine more coal yields 20 total coke and a second named 1000 mB tank, with no residual oven fluid. A **separate, explicitly seeded** 24000 mB tank boundary proves a full tank blocks processing, a 1000 mB container drain frees capacity, and the next coal then yields the 21st coke and 100 mB. That seeded boundary is not presented as cold production.
