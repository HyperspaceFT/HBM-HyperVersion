# Goal 12B isolated coltan, niobium and catalytic cracking regression

Run `python -B -X utf8 tools/migration/verify_goal12b.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal12b/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles (in each of the three worlds). javac receives its file lists through argument files in the run folder.

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Lines starting with `info:` report observed numbers; they are not asserted and are no gameplay claim. Sections 1, 3p, 6, 9t and 12t are text checks run by `verify_goal12b.py` itself and report the same way.

`python -B -X utf8 tools/migration/goal12b_mutation_check.py` breaks 10 Goal 12B decisions one at a time (the deposit centre from `Random(seed + 6)`; the deposit range 750 -> 700; the height bottom + 15 -> + 10; the vein size 4 -> 3; `chem.coltancleaning` back to purified tantalite; the cracking loops 2 -> 1; 50 instead of 100 mB oil per run; 1 instead of 2 mB spent steam per run; the first port facing the other way; 3 instead of 4 niobium ingots in `ass.crackingtower`) in a temporary copy of `src/main/java` under `build/migration/goal12b` and reruns the regression (log: `build/migration/goal12b/mutation_check.log`, one folder per run under `build/migration/goal12b/mutation-runs/`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error. `src/main/java` is hashed before and after; the check fails if it changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere.

`python -B -X utf8 tools/migration/verify_goal12b_resources.py [--source-only]` checks the generated tree against `build/migration/goal12b/stamp-before-g12b.json` (byte for byte the stamp of `3687da34`; 3858 files before, 3906 now = 3858 + 52 - 4: exactly the 52 Goal 12B files added, `en_us.json` and `#minecraft:mineable/pickaxe` modified, the 4 retired coltan block recipes on purified tantalite and their advancements removed and archived under `build/migration/retired/d5506fc4-.../` with their `3687da34` bytes), that the current stamp's inputs match the sources and differ from the pre-Goal 12B stamp in exactly the 67 Goal 12B inputs (24 changed and 7 new Java sources, `zh_cn.json`, 3 imported assets, 32 derived frames; the same set as `git diff`/untracked files under `src/main`), the English delta (+5 keys exactly), the pickaxe tag (+`ore_coltan`, +`machine_catalytic_cracker`), the added files (models, blockstates, loot, the compass's 33 angle overrides at vanilla `compass.json`'s thresholds and its 31 frame models, advancements), `zh_cn.json` (+5 keys with the expected Chinese; the pre-Goal 12B bytes by `git show 3687da34:`), `zh_cn-map.json` (+5 entries: 4 upstream with the original keys and both `.lang` files, 1 local with a reason; 108 deferred keys unchanged), the 3 imported assets against the original files and their SHA-256, the existing `fragment_coltan.png` against the original, and the 32 frames `coltan_tool_00..31.png`: decoded with a pure-Python PNG reader, each is a 16x16 RGBA image whose pixels equal rows 16i..16i+15 of the decoded original `coltass.png` (byte equality is not required: the frames were re-encoded), with the hashes recorded at the derivation (`build/migration/goal12b/coltass-frames.sha256`). Full mode also compares `build/libs/hbmsntm-198A.jar` with the generated files, `zh_cn.json`, the assets and frames and the classes of the 31 changed or new sources, requires the 4 retired files to be absent from the JAR and present in the Goal 12A release, checks the class literals the older scripts use (`GOAL12B_LITERALS`, one per changed source) and writes `build/migration/goal12b/generated-check.json` for `package_goal12b.py`, which keeps the JAR as `build/migration/releases/goal12b/hbmsntm-198A-goal12b.jar` with `SHA256SUMS.txt` and `release.json`, explains every entry of the delta to the Goal 12A release and checks the recorded hashes of the 12A, 11D, 11C, 11B, 11A, 10C, 10B, 10A, 9B, 9A and 8 releases. Its helpers `post_goal12a_bytes`, `post_goal12a_tree`, `post_goal12a_generated`, `post_goal12a_input`, `post_goal12a_stamp`, `same_as_post_goal12a`, `without_goal12b_keys`, `post_goal12a_archive` and `goal12b_delta(check)` are imported by `verify_goal12a_resources.py` (and through its helpers by the 11D, 11C, 11B, 11A and 10C scripts) to read the post-Goal 12A state; this module imports none of them.

Expected numbers come from the original (`Hbm-s-Nuclear-Tech-GIT`, checked out at `d7ef2df`), not from the NEO classes; section 12t requires every transcribed line where it is cited: `HbmWorldGen.java:153-169` (deposit), `ItemColtanCompass.java:46-47, 56-64`, `ModBlocks.java:1326` (hardness 15, resistance 10), `BlockOre.java:96-97, 135-136` (fragment, fortune), `SmeltingRecipes.java:106` (1.0 XP; NEO keeps 0.7, printed), `MineralRecipes.java:47`, `ToolRecipes.java:120`, `CraftingManager.java:462`, `ChemicalPlantRecipes.java:214-221, 311-315`, `AssemblyMachineRecipes.java:316-317`, `CrackingRecipes.java:41-55, 92-94`, `TileEntityMachineCatalyticCracker.java:28-32, 45, 47, 72-85, 98, 109, 125-135, 168, 173`, `TilePort.java:204`, `MachineCatalyticCracker.java:38, 45, 50, 56-59`, `MultiblockHandlerXR.java` (`rotate`, the fill loops), `RefineryRecipes.java:30-33`, `Fluids.java:641`, `SerializableRecipe.java:59, 64`, `HazardRegistry.java:482`, `OreDictManager.java` (~395). `ForgeDirection.getRotation(UP)` is not in the repository; the fixture uses Forge 1.7.10's `ROTATION_MATRIX[UP] = {0, 1, 5, 4, 2, 3, 6}` (north -> east, clockwise from above), the convention the earlier NEO ports (arc welder, steam engine, heat boiler) document. ## Production code under test

Shredder world: the Goal 4 shredder world (`goal11c_regression/stubs.py shredder_stubs`, real Gson) with the production `SerializableRecipe`, `GenericRecipes`, `GenericRecipe` and `ShredderRecipes`, and `ShredderRecipes.java` from `git show 3687da34` moved to `goal12b.head`; the production loader reads and writes a scratch config directory in the run folder. The Goal 11A fixtures `Goal11ABlockAccess` (placement through the production block: `createCoreState`, `fillSpace`, `makeExtra`, `newBlockEntity`) and `Goal11AWorldGen` (the WorldGenRegion model) and the Goal 12A `Goal12AProxyAccess` are compiled unchanged.

Not compiled: `RenderCatalyticCracker` and `CrackingRecipeHandler` (client-only / JEI), `NuclearTechModClient` (the compass needle property), the datagen providers (sections 1, 3p and 6 read the generated JSON), `NtmLanguageProvider`, the registries.

## Stand-ins

`goal12b_regression/stubs.py` extends the Goal 12A machine world:

- registry entries `NtmBlockEntityTypes.MACHINE_CATALYTIC_CRACKER`, `NtmBlocks.ORE_COLTAN` as a real block, the fluids the cracking table names that the earlier worlds lack (new ids after the existing ones, also in `Fluids.fromID`), `NtmDataComponents.COLTAN_X`/`COLTAN_Z`;
- `DummyableBlock.checkRequirement` with the production body (the earlier worlds' stand-in answered true), so the tower's override checks its main box;
- the compass: `Item.inventoryTick` (a no-op default), `ServerLevel.getSeed` (a field the fixture sets), `LoreItem` as a plain item (its tooltip body is not run), `ServerProxy` with the production `ID_COMPASS` read from `ServerProxy.java`, and `NuclearTechMod.proxy.displayTooltip` recording its calls;
- world generation: `WorldGenLevel.getSeed`/`ensureCanWrite` as defaults (the Goal 12B region overrides both; `ensureCanWrite` is Minecraft 1.21.1 WorldGenRegion's write radius 1), `FeaturePlaceContext.chunkGenerator`, a `ChunkGenerator` marker, Minecraft 1.21.1's `Feature.place(config, level, generator, random, origin)` (read from the NeoForge sources: `ensureCanWrite(origin)`, then `place(context)`), `OreConfiguration` with `TargetBlockState` as Minecraft's, `RuleTest`/`TagMatchTest` (`state.is(tag)`), and `Feature.ORE` as a **recording stand-in**: the real 1.21.1 `OreFeature` is not compiled here, so it records every placement (origin, configuration, generator) and draws nothing from the random source. The vein shape, the ore feature's own draws, which blocks it replaces and the y spread of the 1.7.10 vein are not modelled; the placed feature's chunk origin and `WorldgenRandom` seeding are not modelled either (the fixture passes the chunk corner and the random source).

and the Goal 11D recipe world: the Goal 3C name-only `CrackingRecipes` stand-in is dropped (the production class is compiled) and `Fluids` is regenerated with every fluid the cracking table and the fixture name (internal name = field name, as the earlier recipe worlds).

In the machine fixture the chains' fluid sources (crude oil, natural gas, steam) are production barrels in mode 2 and the sinks production barrels in mode 0; the heat boiler is a bare core block entity (no multiblock) whose heat source is a production heating oven the fixture sets to 10,100 TU before every boiler tick; the chemical plants are bare core block entities; the refinery is placed through its production block; the plants' and the refinery's power is refilled by the fixture and sulfur is topped up as a hopper would. Not modelled: rendering, the JEI category, the compass needle (`CompassItemPropertyFunction`), sound, item transport, real chunk saving (the save round trip calls `saveAdditional`/`loadAdditional` directly), packets (`networkPackNT` is counted, the buffer is the stand-in value list), the placement preview, the dedicated server, other mods.
