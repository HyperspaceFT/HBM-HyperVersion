# Goal 10B isolated soldering and arc welding regression

Run `python -B -X utf8 tools/migration/verify_goal10b.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal10b/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles. javac receives its file list through an argument file in the run folder.

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections and the other world still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Sections 3 and 7 are text checks run by `verify_goal10b.py` itself and report the same way.

`python -B -X utf8 tools/migration/goal10b_mutation_check.py` reverts nineteen Goal 10B decisions one at a time in a temporary copy of `src/main/java` under `build/migration/goal10b` and reruns the regression (log: `build/migration/goal10b/mutation_check.log`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error. The source tree is hashed before and after; the check fails if it changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere. Flipping `rot` in `MachineArcWelderBlockEntity.getConPos` is not listed: the ten connections are mirror-symmetric, so that change is behaviourally equivalent (section 6 checks the symmetry); the observable flips (the arc welder block's `fillSpace`, the soldering station's connections) are listed.

`python -B -X utf8 tools/migration/verify_goal10b_resources.py [--source-only]` checks the D1-D6 source lines against the original's text (bolt count, stamp conversions, the matcher rule, the welder and solderer `PortDef`s, `MultiblockHandlerXR.rotate` in both repositories, the electrode recipes), the generated `77.json`-`79.json`, and the English and Chinese names of the chain. Full mode also compares the generated output with `build/migration/goal10b/stamp-before-g10b.json`: 3843 files before and after, only `recipe/78.json` and `recipe/79.json` modified, the six changed generation inputs, and `en_us.json` unchanged. `package_goal10b.py` checks and keeps the built JAR after that, relative to the Goal 10A release.

Expected numbers come from the original at `608fec4`, not from the NEO classes: `AnvilRecipes.java:383-389` (soldering station: 2 steel cast plates, 4 copper coils, 4 tungsten bolts, 2 vacuum tubes, tier 2) and `:592-598` (each flat stamp makes its own stamps), `SerializableRecipe.java:431-458` and `ArcWelderRecipes.java:137-174` (matching), `SolderingRecipes.java:44-52` and `:168-187` (analog board, tier-I upgrades), `TileEntityMachineSolderingStation.java:95-135` (formulas, `maxPower = consumption * 20`, idle 2,000), `ArcWelderRecipes.java:57-58` and `TileEntityMachineArcWelder.java:98` (welded steel), `TilePortShapes.java:111-121`, `TileEntityMachineArcWelder.java:216-232` and `TilePort.java:217-225` (ports), `CraftingManager.java:311-313` (electrodes).

## Production code under test

Anvil world (the Goal 3A anvil stand-ins): `AnvilRecipes`, `AnvilSmithingRecipe`, `AnvilSmithingCastMoldRecipe`, `InventoryUtil`, plus `AnvilRecipes.java` as committed at the Goal 9B commit `ee8f8d06` (HEAD when Goal 10B was delivered; read with `git show`; Goal 10A did not touch it), moved to the package `goal10b.head`.

Machine world: everything the Goal 9B regression compiles (energy and fluid networks, cables, ducts, barrels, battery socket and its proxies, `MachineBaseBlockEntity`, `MetaHelper`, `FluidTank`, the boilers, the steam engine, the condenser, `AnvilRecipes`), plus `SolderingRecipes`, `ArcWelderRecipes`, `MachineSolderingStationBlockEntity`, `MachineArcWelderBlockEntity`, `MachineArcWelderBlock`, `MultiblockHandlerXR`, `DummyBlockType` and `IConditionalInvAccess` (the Goal 3B stand-in of that interface is dropped: it lacks the production default `canInsertItem`); and `SolderingRecipes.java` / `ArcWelderRecipes.java` as committed at `ee8f8d06` (package `goal10b.head`), used for the table comparison and to show which cases the matcher change alters.

Not compiled: `MachineSolderingStationBlock` (it has no `fillSpace` override; its connections are checked through the block entity), `DummyableBlock` (a stand-in, below), the menus, screens and renderers (stand-ins or client-only), the JEI categories, `NtmRecipeProvider` (section 7 reads its text).

## Stand-ins

`goal10b_regression/stubs.py`, anvil world, is the Goal 3A anvil world with:

- `CastPlateItem.Type` and `BoltItem.Type` generated from the production enums (cast plate META = ordinal, STEEL 11; tungsten bolt META 7400);
- `NtmItems.castPlateIngredient` returning `ComparableStack(CAST_PLATE, count, type.ordinal())`, the production rule (`NtmItems.java:1150-1152`); the Goal 3A stand-in used a separate item per type without META.

Machine world, the Goal 9B world with:

- the registry names `SolderingRecipes`/`ArcWelderRecipes`/the two machines use, declared in `NtmItems`/`NtmBlocks`; `NtmItems.Ref` extends a `DeferredItem<Item>` stand-in (the recipe tables take `DeferredItem<Item>`); `castPlateWeldedIngredient` with the production rule;
- `CastPlateItem.Type`, `PartGenericItem.Type` (ordinals) and `WireDenseItem.Type` (META values) generated from the production enums; the fluids the tables name appended to the `Fluids` stand-in;
- `RecipesCommon.ComparableStack(ItemStack)` (item, count, META), as in production; `ComparableStack.matchesRecipe` keeps the Goal 8 stand-in, which follows production `RecipesCommon.java:159-168` (item, META unless wildcard, count unless ignored);
- a `SerializableRecipe` stand-in (abstract handler methods, inert JSON helpers): the JSON path is not exercised;
- `IUpgradeInfoProvider.KEY_DELAY`, `ChatFormatting.DARK_GRAY`, `IFluidCopiable.getTankToPaste` as a default method (as in production), the two menus as empty `AbstractContainerMenu`s;
- display stacks: `ItemStack.save` wraps a copy in a `CompoundTag`, `parse`/`parseOptional` unwrap it; `writeNbt`/`readNbt` are one entry in the Goal 9B ordered buffer; `Level.registryAccess()` is null;
- blocks: `BlockState` keeps the Goal 9B `facing` model for `FACING` and stores the `TYPE` `EnumProperty` per state; `setValue` returns a new state; `Block.defaultBlockState()`; `Level.setBlock` stores the state (no block entity is created, no neighbour update runs); `canBeReplaced()` is true for the plain block;
- `DummyableBlock` is a stand-in that extends `Block` and declares the hooks `MachineArcWelderBlock` overrides; its `fillSpace` and `makeExtra` are the production method bodies, copied from `DummyableBlock.java` when the stand-ins are built. Placement (`setPlacedBy`, `checkSpace`), breaking, shapes and highlights are not modelled;
- `NuclearTechMod.LOGGER` records warnings (used by `MultiblockHandlerXR`), `MapCodec`, `BlockEntityTicker`, `StringRepresentable` stand-ins.

`UpgradeManagerNT` stays the earlier stand-in from the Goal 3B network world (level 0 for every upgrade); every run here has empty upgrade slots, where production also gives level 0. `Library.chargeTEFromItems` returns the power it is given (no battery in the machines' battery slots).

## Sections

Anvil world:

1. Anvil: the live construction list equals the committed one at every index except exactly seven entries: the soldering station's tungsten bolts 1 -> 4 and the six titanium/steel stamp conversions (titanium flat -> titanium plate/wire/circuit, steel flat -> steel plate/wire/circuit), each pair in its adjacent positions; Goal 10C (`migration/GOAL10C.md`) appends three heating oven entries after the committed list, which are required exactly (live size = committed size + 3; `verify_goal10b_resources.py` likewise requires and removes the exact Goal 10C source block, `goal10c_regression/anvil_block.py`, before its seven-line comparison; Goal 11A (`migration/GOAL11A.md`) appends two fluid burner entries after those, required exactly at the end with one more check, and the resource script first removes the exact Goal 11A block, `goal11a_regression/anvil_block.py`); the smithing list is unchanged entry by entry; the soldering station entry is 2 vacuum tubes, 4 copper coils, 2 steel cast plates (META 11), 4 tungsten bolts (META 7400) -> one plain soldering station, tier 2 and up, construction overlay.

Machine world:

2. Matching: both tables equal the committed ones entry by entry (D2 changes only the matcher); every ingredient is a `ComparableStack` (no tag ingredient) and every group fits its slots; each of the 39 soldering and 42 arc welder recipes is returned by `getRecipe` for exactly its own ingredients; the analog board and speed upgrade I as in the original; for 15 soldering and 11 arc welder cases the live result and the committed matcher's result (stray item, a microchip or steel plate that can really be inserted, an item in an empty group's slot, a missing ingredient, one below a count, an ingredient in two slots, more than enough, other slots of a group, the wrong group, a wrong META, nothing); first match in list order (a duplicate recipe appended and then moved to the front).
4. Soldering station: analog board 100 ticks, 100 HE/t, 2,000 HE, output after exactly 100 ticks, exact consumption also from larger stacks, progress reset every tick below 100 HE, a microchip in slot 2 blocks it; speed upgrade I 200 ticks, 1,000 HE/t, 20,000 HE, lead wire in the solder slot blocks it. The buffer is refilled to `maxPower` before every tick, as a powered network keeps it full (the station's `getPower` clamps to `maxPower`).
5. Arc welder: 8 slots (no electrode slot) and no recipe takes an electrode; welded steel plate 100 ticks, 500 HE/t, 10,000 HE, output after exactly 100 ticks; a steel plate in slot 1 blocks it; below 500 HE progress resets.
6. Connections, for all four facings: the original `rot` is derived from the real `MultiblockHandlerXR.rotate` applied to the solderer dimensions (the side the footprint occupies besides the block behind the core); the soldering station's `getConPos` equals the expansion of the original four `PortDef`s and the arc welder's the ten connections of the original six `PortDef`s (as a set with directions); every connection is outside the rotated footprint, on the bottom layer, facing away from a footprint block; the former `(core + rot, rot)` lies inside the footprint and is gone; the welder's set is mirror-symmetric. `fillSpace` through the real `MachineArcWelderBlock` in the stand-in level: 12 blocks, the core CORE, the five bottom blocks and the four upper core/+rot blocks EXTRA, the two upper -rot blocks DUMMY (recorded NEO difference: the original makes every dummy a proxy), `makeExtra` changes only `TYPE`, the block behind every connection is CORE or EXTRA, and `newBlockEntity` gives the welder, an inventory/power/fluid proxy, or nothing. Through the real power network, for each of the 10 welder and 8 solderer connections, a battery socket in output mode feeds a cable at that point and the idle machine fills to 2,000 HE (exactly what the socket sends); cables two blocks in front and at a diagonal corner power nothing.
6b. Arc welder item routing (added after the independent review: with the strict match, one feeder that spreads an ingredient over two input slots would stop the machine), for all four facings: `getAccessibleSlotsFromSide` gives red `{0,3}` at core+rot and core-rot-dir, yellow `{1,3}` at core-dir, green `{2,3}` at core-rot and core+rot-dir from every side, nothing for the six upper blocks, and the core's own `getSlotsForFace` is `{1,3}` (original `TileEntityMachineArcWelder.java:282-331`); inserts reach slots 0-2 only and only recipe ingredients (NEO keeps its ingredient filter; the original accepts anything); only slot 3 is extracted; one proxy reaches exactly one input slot; 64 steel cast plates in slot 0 alone still match, split over slots 0 and 1 they do not. The proxy dispatch itself (`ProxyComboBlockEntity`) and the hopper's slot choice are not run.

## Not covered

- Minecraft itself: real block placement (`setPlacedBy`, `checkSpace`, neighbour updates, block entity creation on `setBlock`), chunk loading, the server tick order, the network's 3 s subscription timeout, packets and payload codecs, data components beyond META, registries, item stacking limits, menus and slots, screens, JEI categories, rendering, sounds, the original's particle packet, dedicated servers and gameplay.
- Proxies: the welder's `ProxyComboBlockEntity` flags are read from `newBlockEntity`; hopper or pipe access through a proxy is not exercised, and NEO's per-face slot access (every face 0-3) is not compared with the original's per-block slots.
- Upgrades (speed, power, overdrive) in the machines' upgrade slots, battery charging from slot 7/4, fluid identifiers and fluid recipes, the soldering station's collision prevention, NBT save/load and sync of both machines.
- The recipe JSON path (`hbmSoldering.json`, `hbmArcWelder.json`).
