# Goal 13B isolated arc furnace, silicon wafer and chip chain regression

Run `python -B -X utf8 tools/migration/verify_goal13b.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal13b/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles (in each of the two worlds). javac receives its file lists through argument files in the run folder. `--only recipe|machine` runs one Java world for development (and always ends in a failed "partial run" exit). The post-Goal 13A copies of `AssemblyMachineRecipes` and `PressRecipes` live in `build/migration/goal13b/base-g13a` (byte copies of the Goal 13A final source tree, `build/migration/goal13a/src-copy-final`); the script checks each against the hash the post-Goal 13A stamp (`build/migration/goal13b/stamp-before-g13b.json`) records before it compiles it, because Goal 13A is uncommitted work and git cannot give its state.

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Lines starting with `info:` report observed numbers; they are not asserted and are no gameplay claim. Sections 1t, 2t, 3p, 4t, 8t and 13t are text/JSON checks run by `verify_goal13b.py` itself and report the same way.

`python -B -X utf8 tools/migration/goal13b_mutation_check.py` breaks 18 Goal 13B decisions one at a time (the lid rate 1/60 -> 1/50; the processing duration 400 -> 300; the delay 120 -> 100; the consumption base 1,000 -> 500; the graphite electrode maximum 10 -> 20; `damage` returning `durability > maximum` instead of `>=`; only the first electrode replaced by its burnt item; one extra proxy position flipped; the queue cap ignoring the output count; the sync range 150 -> 100; the lid loop volume 0.75 -> 0.5; the sand default 1 -> 2 nuggets; the de-duplication removed from `register`; `ass.chip` outside the `!enable528` block; `ass.arcfurnace` any-concrete 12 -> 10; the silicon billet press entry removed; the burnt electrode experience 3.0 -> 1.0; the silicon billet recipe built from the uranium nugget) in a temporary copy of `src/main/java` under `build/migration/goal13b` and reruns the regression (log: `build/migration/goal13b/mutation_check.log`, one folder per run under `build/migration/goal13b/mutation-runs/`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error. `src/main/java` is hashed before and after; the check fails if it changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere. The datagen providers are not compiled: the two provider mutations are detected through the text of the mutated copy that sections 1t and 2t read (the generated JSON cannot change in a source copy). `NtmItems` is not compiled either, but `goal13b_regression/stubs.py` builds the four electrodes of the stand-in registry from the production `NtmItems` text (stack size, maximum, burnt item), so the electrode maximum mutation reaches the compiled item test; every other mutation is in a compiled source.

`python -B -X utf8 tools/migration/verify_goal13b_resources.py [--source-only]` checks the generated tree against `build/migration/goal13b/stamp-before-g13b.json` (the stamp after the final Goal 13A runData; 3927 files before, 3948 now = 3927 + 21: exactly the 21 Goal 13B files added, `en_us.json` and the pickaxe tag modified, nothing removed), that the current stamp's inputs match the sources and differ from the pre-Goal 13B stamp in exactly the 31 Goal 13B inputs (19 changed and 8 new Java sources, `zh_cn.json`, 3 imported assets), and that `git` lists, against 12f38317, exactly the Goal 13A and Goal 13B inputs together (the Goal 13A set is the difference between the stamp of 12f38317 and the pre-Goal 13B stamp). It checks the English delta (+4 keys and the corrected `item.hbmsntm.circuit_microchip`, against the Goal 13A release JAR's `en_us.json`), the pickaxe tag (+`hbmsntm:machine_arc_furnace`), `zh_cn.json` (+4 keys with the expected Chinese), `zh_cn-map.json` (+4 entries: 3 upstream with the original keys and both `.lang` files, 1 local with a reason; the microchip entry from the local "Microschip" entry of 12f38317 to the upstream entry for "Microchip"; 108 deferred keys unchanged) and the 3 imported assets against the original files, their SHA-256 and `migration/goal13b-resource-ownership.json`. Full mode also compares `build/libs/hbmsntm-198A.jar` with the generated files, `zh_cn.json`, the assets and the classes of the 27 changed or new sources, checks one class literal for each (`GOAL13B_LITERALS`; `None` where the change adds no string: the class must then differ from the Goal 13A release) and writes `build/migration/goal13b/generated-check.json` for `package_goal13b.py`, which keeps the JAR as `build/migration/releases/goal13b/hbmsntm-198A-goal13b.jar` with `SHA256SUMS.txt` and `release.json`, explains every entry of the delta to the Goal 13A release (no new directory entry: every new file lands in a directory the release already has) and checks the recorded hashes of the 13A, 12B, 12A, 11D, 11C, 11B, 11A, 10C, 10B, 10A, 9B, 9A and 8 releases. The post-Goal 13A state (the Goal 13A release JAR for the three files Goal 13B changes, the pre-Goal 13B stamp for the rest, the reviewed map reconstructed as the current map without the 4 new entries and with the microchip entry at 12f38317) is offered through `post_goal13a_bytes`, `post_goal13a_tree`, `post_goal13a_generated`, `post_goal13a_input`, `post_goal13a_stamp`, `post_goal13a_zh_map`, `same_as_post_goal13a`, `post_goal13a_archive` and `goal13b_delta(check)`; `verify_goal13a_resources.py` reads its own state through them (and so do all older resource scripts, through its `post_goal12b_*` helpers); this module imports none of the older ones.

Expected numbers come from the original (`Hbm-s-Nuclear-Tech-GIT`, checked out at `d7ef2df`), not from the NEO classes; section 13t requires every transcribed line where it is cited: `TileEntityMachineArcFurnaceLarge.java:56, 80-81, 108-109, 117, 120, 127, 129-145, 151-164, 187, 201-258, 263-301, 303-316, 318-328, 350-351, 369-416, 554-561, 567-624, 708-727`; `ItemArcElectrode.java:14, 22-52`; `MachineArcFurnaceLarge.java:28-64`; `ContainerMachineArcFurnaceLarge.java:27-44`; `GUIMachineArcFurnaceLarge.java:37-38, 47, 65-66, 76, 79, 82`; `ModBlocks.java:1824`; `ArcFurnaceRecipes.java:53-65, 135-150`; `AssemblyMachineRecipes.java:126-128, 286-288`; `PressRecipes.java:99`; `MineralRecipes.java:154, 549-563`; `SmeltingRecipes.java:112-115`; `SolderingRecipes.java:54-60`; the four `en_US.lang` texts of the upstream keys. ## Production code under test

## Stand-ins

`goal13b_regression/stubs.py` extends the Goal 13A worlds:

- the client branch of the block entity: `SoundUtils.playAtVec3` for the block centre, `ParticleUtil.addParticle` recording each particle, `NbtParticleOptions`, `NtmParticleTypes`, `Player.distanceToSqr` over a position the fixture sets, `AudioWrapper` from Goal 13A (parameters, start, stop, keep-alive), `NuclearTechMod.proxy.playLocalSound` from Goal 12A;
- `RecipesCommon.ComparableStack` in the machine world with the production `makeSingular`, `equals` and `hashCode`; in the recipe world the whole `RecipesCommon` is replaced by the production semantics the tables call (`AStack`, mutable `meta`, `matchesRecipe`, `equals`/`hashCode`, a `TagStack` matching through the item's tag list; the members of a tag the table resolves while registering are fixture-set in `RecipesCommon.TAG_MEMBERS`, empty by default as the tags are not bound while the defaults load);

The Goal 3C name-only `ArcFurnaceRecipes` and `PressRecipes` handler stand-ins are dropped in the recipe world (the production classes are compiled).

Not modelled: the client rendering (the renderer is read as text, the OBJ's parts are checked by name), the GUI drawing, JEI, sound playback (the loop parameters are checked), the real `RecipeManager` and tag binding (the tag members are fixture-set), the real `BlockEntity` ticker scheduling (the fixture calls `updateEntity` once per tick), world saves and chunk loading (`saveAdditional`/`loadAdditional` run through reflection), packets (`networkPackNT` is counted, `serialize`/`deserialize` round-trip through the buffer stand-in), the dedicated server, other mods, the ore dictionary (tags are strings), the energy network's cable transfer into the furnace (the power is set directly or comes from a battery stand-in; the proxies are checked as block entities and positions).

## Reading the numbers

The observed numbers are the production code's, not gameplay claims: the lid closes in 61 float steps (not 60) and processing at upgrade 0 takes 401 (not 400) because the original sums `1F / 60` and `1F / 400` in `float` (the same effect as the 301 ticks of `ass.factorioChip` in Goal 13A); 33 -> 35 assembler recipes and the 27 -> 28 press entries are the counts of the stand-in worlds' production tables after Goal 13A and now.

## Older suites

Goal 13B moves several things the older suites assert (see the report): `SerializableRecipe.registerAllHandlers` gains `ArcFurnaceRecipes` (a handler count in the Goal 10A, 11D and 12B suites, a compiled class name in every recipe world), `AssemblyMachineRecipes` gains `ass.chip` and `ass.arcfurnace` (the tail checks of the Goal 11A, 11B, 11C, 12B and 13A recipe fixtures), `PressRecipes` gains a `StampType.CIRCUIT` entry (the Goal 2 and 3A stand-ins), and the generated tree moves (the resource scripts of Goal 13A and before). The suites were converted without deleting or relaxing an assertion: each says what it accepts (the stand-in handler name in `goal3c_recipe_regression/stubs.py`, the `StampType` and item names in `verify_goal2.py`, one added check each for the assembler tail and the handler registration, `verify_goal13a_resources.py` and through it every older resource script reading the post-Goal 12B state through the post-Goal 13A helpers of `verify_goal13b_resources.py`), and each converted suite's README says so in one sentence.
