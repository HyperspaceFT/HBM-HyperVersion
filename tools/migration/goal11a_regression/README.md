# Goal 11A isolated oil extraction regression

Run `python -B -X utf8 tools/migration/verify_goal11a.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal11a/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles. javac receives its file lists through argument files in the run folder.

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Sections 3b, 6 and 8 are text checks run by `verify_goal11a.py` itself and report the same way. A run on the real production source also copies the two recipes exported in section 2 to `build/migration/goal11a/recipe-reference/` (`ass.drill_titanium.recipe.json`, `ass.machine_oil_derrick.recipe.json`, written by the production `GenericRecipes.writeRecipe`, as `migration/goal3c-ass-shredder.recipe.json`).

`python -B -X utf8 tools/migration/goal11a_mutation_check.py` reverts or breaks 28 Goal 11A decisions one at a time (the last four are the review fixes: the integer `r^2 / 2` test back, `requiresCorrectToolForDrops` removed from `ore_oil`, `shouldCool = false` moved back inside `toBurn > 0`, `setChanged` removed from `pasteSettings`) in a temporary copy of `src/main/java` under `build/migration/goal11a` and reruns the regression (log: `build/migration/goal11a/mutation_check.log`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error, and an exception next to a detection is logged as `also crashed`. The datagen providers are mutated as text and the generated JSON is not regenerated, so those mutations are caught by the provider-text checks of sections 3b, 6 and 8. The source tree is hashed before and after; the check fails if it changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere.

`python -B -X utf8 tools/migration/verify_goal11a_resources.py [--source-only]` checks the generated tree against `build/migration/goal11a/stamp-before-g11a.json` (3850 files before and after: exactly `en_us.json`, `data/hbmsntm/loot_table/blocks/ore_oil.json` and `data/hbmsntm/worldgen/placed_feature/oil_bubble_placed.json` modified, nothing added or removed), that the current stamp's generation inputs match the sources and differ from the pre-Goal 11A stamp in exactly the 15 Goal 11A inputs (13 Java sources, `zh_cn.json`, the structure tag), the content delta of the three generated files, the English and Chinese deltas (24 fluid keys added, 23 former keys removed and each renamed to one new key with the same English, the two burner descriptions without the hand drill sentence, `container.oil_well` 石油钻井平台 -> 钻油塔; 2115 and 2007 keys; the pre-Goal 11A bytes are read from the Goal 10C release JAR after checking them against the stamp), the 24 names and `container.oil_well` against the original `en_US.lang`/`zh_CN.lang`, the `zh_cn-map.json` entries, `migration/goal11a-resource-ownership.json` and the tag file. Full mode also compares the built JAR's entries with the generated files, `zh_cn.json`, the tag and the classes of the 13 Java sources, and writes `build/migration/goal11a/generated-check.json` for `package_goal11a.py`, which keeps the JAR as `build/migration/releases/goal11a/hbmsntm-198A-goal11a.jar` and explains every entry of the delta to the Goal 10C release. After Goal 11B (`migration/GOAL11B.md`) `verify_goal11a_resources.py` runs its unchanged checks against the post-Goal 11A state (the pre-Goal 11B stamp `build/migration/goal11b/stamp-before-g11b.json`, the Goal 11A release JAR, and the git-free snapshot `build/migration/goal11b/base-g11a/` for the inputs and the map Goal 11B changes; for `AssemblyMachineRecipes.class` and `NtmLanguageProvider.class`, which Goal 11B changes again and for which no post-Goal 11A build exists, the release class must lack the Goal 11B literal `ass.tank` / `overlay.repair_with` that the current build's class holds), then `goal11b_delta()` checks that post-Goal 11A -> now is exactly the Goal 11B set (4 more checks). ## Stand-ins

`goal11a_regression/stubs.py` starts from the Goal 10C machine world (`goal10c_regression/stubs.py`) and adds:

- registry entries for the derrick, fracking tower and burner block entity types; the oil blocks `NtmBlocks` names as blocks (`ORE_OIL`, `ORE_OIL_EMPTY`, `ORE_BEDROCK_OIL`, `OIL_PIPE`, the oily dirt/sand, `STONE_CRACKED`, `OIL_SPILL`, the gases, `MACHINE_WELL`, `MACHINE_FRACKING_TOWER`) as real `Block` instances with their registry id;
- a block identity model: `Block` carries an id, tag keys, an explosion resistance (bedrock 3,600,000, reinforced deepslate 1,200) and `asItem()`; `Blocks` holds real constants for the Minecraft blocks the sources name and the fixture places (stone and its variants, deepslate, tuff, ores, dirt, grass, sand, gravel, water, air, bedrock, tuff bricks and other trial chamber blocks); `BlockTags.BASE_STONE_OVERWORLD` holds exactly the members Minecraft 1.21.1's `VanillaBlockTagsProvider` gives it (read from the NeoForge sources JAR when the stand-ins are built); `BlockState` answers `isAir()` by id, `is(TagKey)`, `canBeReplaced`, `isSolidRender` and `getFluidState`; `BlockPos` is a class with `MutableBlockPos`, and `Level.setBlock` stores immutable keys;
- `Direction` as Minecraft's (order, `getAxis()` X/Y/Z, `from3DDataValue`, `allShuffled` with `Util.shuffle`'s algorithm);
- world generation: `Feature`, `FeaturePlaceContext`, `WorldGenLevel`, `ChunkAccess` with structure references (`getAllReferences`), `Structure`, `Registry`/`RegistryAccess`/`Registries`, `TagKey`, `Holder.is(TagKey)`, `SectionPos`, `LongSet`, `Biome`; `NtmTags.Structures.OIL_BUBBLE_AVOID` with the production id;
- the fuels with their production traits: `Fluids.OIL`, `GAS`, `HEATINGOIL` get `FT_Flammable` from the production `registerCalculatedFuel` formula and `round()` (compiled from `Fluids.java`) and `FT_Polluting` from the production `P_OIL`/`P_GAS` chains; `FT_Polluting` carries the production `burn`/`release` bodies; `PollutionHandler` records every call (level, position, type, amount);
- `Goal11ACrucibleProbe`: the production `MachineCrucibleBlockEntity.tryPullHeat()` body and `MAX_HEAT`, copied verbatim onto a probe with a level and a position (the crucible itself needs casting, mold and material services this world does not have);
- `OilSpot` (counts calls), `SoundUtils` (records plays), the derrick and burner menus, `IFluidCopiable.getSettings` (the copy tool is not exercised), `DummyableBlock.checkRequirement`.

`Goal11ABlockAccess.place` places a derrick or burner like the server branch of `DummyableBlock.setPlacedBy` (core state, then the production `fillSpace`, which places the derrick legs and the burner extras), then creates each part's block entity through the production `newBlockEntity`.

The world-generation model (`Goal11AWorldGen.Region`) follows Minecraft 1.21.1's `WorldGenRegion` during the FEATURES step: `getChunk` at chessboard distance 0-1 from the generating chunk returns the chunk with its blocks and structure references; at 2-8 a chunk at STRUCTURE_STARTS without blocks or references (the guaranteed minimum; a real chunk there may be further generated); beyond 8 it throws "Requested chunk unavailable during world generation"; `getBlockState` reads through `getChunk`; `setBlock` outside the write radius 1 is refused and counted (`ensureCanWrite`). The tag binding is a registry whose holders carry `#hbmsntm:oil_bubble_avoid` for the structures listed in the tag file (the fixture receives the file's `values`). Not modelled: real chunk status progression and its timing, the placement modifiers (`in_square`, `height_range`; section 3b checks their JSON), the decoration seed, biome placement, heightmaps, other features writing the same chunks, and structure pieces themselves (only references).

## Recorded differences and observations

- Bubble shape (resolved by a review fix): NEO's `spawnOil` used to divide `r^2 / 2` as an integer, the original (`MapGenBubble.java:63`) as a double, so for odd radii NEO left out the shell `x^2 + z^2 + 3y^2 == (r^2 - 1) / 2` (radius 9: 599 of 639 blocks, 13: 1823 of 1855, 15: 2793 of 2897; 11 has no such points). `spawnOil` now tests `distSq * 2 < r2`, and section 3 asserts the block count and the block set equal the original's at every radius 8..15 and that the shell is included; the mutation `distSq < r2 / 2` is detected.
- Surface spots: `addSurfaceSpot` scans columns up to about 3.5 x 7 blocks from the centre, which can lie outside the 3x3 (read as STRUCTURE_STARTS chunks in the model, nothing written); in the game such a chunk may be further generated, so those reads may depend on the generation order. Neighbouring bubbles' spots can overlap, so the full block map of adjacent bubbles depends on the generation order (decisions, radii and oil rock do not).
- The connection test at the former corner points uses a bare core without legs, because a real placement puts legs there.
- The drain and chain sections step the derrick by setting the clock to the next multiple of its delay with full power and empty tanks (drain) or in real ticks (chain).
