# Goal16B isolated verification boundaries

These runners use the already installed Python/JDK21 and cached Gson/NeoForge inputs. They never launch Minecraft, a server, Gradle game tasks or download dependencies. Each run writes a fresh UUID directory beneath `build/migration/goal16b`; earlier failure logs remain available.

- `verify_goal16b_recipes.py`: production centrifuge recipes, loader, packet, client and sync methods, plus the frozen original NEO class compiled under another class name. Compares all76 default rows, input/output components, quantities and order, then actual writer/parser roundtrips. Declared registry/component/SNBT, event recipients, queue, buffer and JEI manager services are isolated. Only the actual JEI refresh body is extracted; the lifecycle bridge is a fixture. Every used registrationID is checked against real declarations.
- `verify_goal16b_machine.py`: actual machine BE/menu/Library/upgrade/energy-network/inherited inventory methods. Recipe queries and client cache are explicit services, cross-referenced to the separate real recipe checks. World, NBT, audio and some engine/container services are substitutes. Finite coal and40000HE are explicit initial inputs; upstream manufacture is not executed. Assertions/scenarios and repeated tick executions are counted separately.
- `verify_goal16b_structures.py`: extracted production four-cell placement/ownership/removal/player-destroy methods and synthetic world/loot services. Mutations must compile successfully, then fail behavior assertions. A compiler failure does not count as a detected regression.
- `verify_goal16b_acquisition.py`: real AssemblyMachineRecipes/GenericRecipes registration, writer and parser; frozen pre16B assembly class provides the baseline. Both528 settings retain every old row, ordering and pool; exactly the two ordinary centrifuge outputs are added. Registry/tag bindings are explicit services. Material source graph is static evidence, not survival manufacture.
- `verify_goal16b_affected.py`: unchanged16A mixer recipe fixture and assertions against current source; only the output boundary is redirected in memory. Old test files and their assertions remain byte-identical.
- `verify_goal16b_resources.py` and `package_goal16b.py`: final generation-source hashes, one new bilingual key, existing108deferrals, asset provenance, all old release bytes and actual-start bounded file changes; JAR byte/class/resource checks and correct16B report indexes.

Production/fixture/adapter/cache/compiled-input hashes and exact commands are in each report. Early fixture failures are retained and are not production findings or passing checks. Compilation, datagen and `test NO-SOURCE` are not real gameplay/save/UI/multiplayer/dedicated-server or no-JEI launch acceptance. Those remain in `migration/GOAL16B-ACCEPTANCE.md` and the feature stays `partial-unverified`.
