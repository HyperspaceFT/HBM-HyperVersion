# Goal 11C isolated chemical plant and desh regression

Run `python -B -X utf8 tools/migration/verify_goal11c.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal11c/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles (in each of the three worlds). javac receives its file lists through argument files in the run folder.

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Lines starting with `info:` report observed numbers; they are not asserted and are no gameplay claim. Sections 2t and 7t are text checks run by `verify_goal11c.py` itself and report the same way. A run on the real production source also copies the recipes exported in sections 1 and 4 to `build/migration/goal11c/recipe-reference/` (`ass.chemplant.recipe.json`, `chem.polymer.recipe.json`, written by the production `GenericRecipes.writeRecipe`).

`python -B -X utf8 tools/migration/goal11c_mutation_check.py` reverts or breaks 12 Goal 11C decisions one at a time (`ass.chemplant` removed, with 8 instead of 16 polymer plates, made pooled; the selection check removed; the per-tick pool check removed; `chem.polymer` back to 500 mB and, separately, back to 1 ingot; the shredder chunk entry removed; `canTakeItemThroughFace` back to 7-9; `quickMoveStack` back to `super`; the container slots conditional again (the post-Goal 11B lines); `chem.desh` back to 戴斯合金生产) in a temporary copy of `src/main/java` under `build/migration/goal11c` (the `chem.desh` mutation in a copy of `zh_cn.json` in a temporary resource root that `verify_goal11c.py` reads instead) and reruns the regression (log: `build/migration/goal11c/mutation_check.log`, one folder per run under `build/migration/goal11c/mutation-runs/`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error, and an exception next to a detection is logged as `also crashed`. `src/main/java` and `zh_cn.json` are hashed before and after; the check fails if they changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere.

`python -B -X utf8 tools/migration/verify_goal11c_resources.py [--source-only]` checks the generated tree against `build/migration/goal11c/stamp-before-g11c.json` (3850 files before and after: nothing modified, added or removed; the generated fingerprint unchanged), that the current stamp's generation inputs match the sources and differ from the pre-Goal 11C stamp in exactly the 7 Goal 11C inputs (6 Java sources and `zh_cn.json`), that the git-free snapshot `build/migration/goal11c/base-g11b/` is the post-Goal 11B state (its stamp, its generated files and the 7 inputs against the pre-Goal 11C stamp), that `en_us.json` is unchanged (2116 keys) and `zh_cn.json` (2008 keys) changes exactly `chem.desh` 戴斯合金生产 -> Desh生产 (the pre-Goal 11C bytes are read from the Goal 11B release JAR after checking its SHA-256), that every Chinese name of an English "Desh" entry says Desh and no 戴斯 is left, that the original `zh_CN.lang` has no `chem.desh`, and that `zh_cn-map.json` changes only the `target_zh` of that local entry (2116 entries, 108 deferred). Full mode also compares the built JAR's entries with the generated files, `zh_cn.json` and the classes of the 6 Java sources, and writes `build/migration/goal11c/generated-check.json` for `package_goal11c.py`, which keeps the JAR as `build/migration/releases/goal11c/hbmsntm-198A-goal11c.jar` with `SHA256SUMS.txt` and `release.json`, explains every entry of the delta to the Goal 11B release and checks the recorded hashes of the 11B, 11A, 10C, 10B, 10A, 9B, 9A and 8 releases. Its `goal11c_delta(check)` (post-Goal 11B -> now is exactly the Goal 11C set, 3 checks) and constants are imported by `verify_goal11b_resources.py`, `verify_goal11a_resources.py` and `verify_goal10c_resources.py`, which read the post-Goal 11B state from them; this module imports none of them. Goal 11D (`build/migration/goal11d/production.diff`) changes one further generation input, `SerializableRecipe.java`, which Goal 11C left as it was: `verify_goal11c_resources.py` reads that input as committed at `1e29ad29` (`post_goal11c_bytes()` from `verify_goal11d_resources.py`) and the pre-Goal 11D stamp `build/migration/goal11d/stamp-before-g11d.json` as the post-Goal 11C stamp, and `goal11d_delta()` from that module checks that post-Goal 11C -> now is exactly the Goal 11D set (3 more checks).

Expected numbers come from the original (`Hbm-s-Nuclear-Tech-GIT`, checked out at `d7ef2df`; the delta to the planning baseline `608fec4` changes none of these files except `ModBlocks.java`, whose cited line is unchanged and only moved from 2258 to 2262, `migration/UPSTREAM-REVIEWS.md` Goal 11C-0), not from the NEO classes: `AssemblyMachineRecipes.java:264-265` (`ass.chemplant`, normal mode: 200 ticks, 100 HE/t, 8 steel ingots and 2 copper pipes (ore dictionary), 16 polymer plates, 2 motors, 2 tungsten coils, 1 analog circuit -> 1 chemical plant, no blueprint pool; the expensive inputs of `:266` use `item_expensive`, `ass.chemplantAlt` at `:267-269` is not ported); `ModuleMachineBase.java:181-184` (`setRecipe` stores the name), `:188-196` (`update`: a pooled recipe whose blueprint is missing is dropped, recipe `"null"`, progress 0, no run, `:191-195`); `TileEntityMachineChemicalPlant.java:108-110` (the three input container slots load every tick, before the module update at `:126`), `:241-242` (`canExtractItem`: 7-9 or a clogged input), `:264-272` (`receiveControl` index 0 stores the selection); `ContainerMachineChemicalPlant.java:43-78` (battery -> 0, blueprint -> 1, upgrades -> 2-3, anything else only into 4-6 through `InventoryUtil.mergeItemStack`, which asks `isItemValid`); `ChemicalPlantRecipes.java:196-201` (`chem.desh`: 1 desh blend, 200 mB light oil, 200 mB mercury -> 1 desh ingot, 100 ticks, 100 HE/t; the LBSM simple-chemistry branch is not ported), `:209-212` (`chem.polymer`: 2 coal powder, 1 fluorite, 1,000 mB petroleum gas -> 4 polymer ingots, 100 ticks, 100 HE/t; the 528-mode pressure is not ported); `ShredderRecipes.java:208` (the RARE ore chunk -> 1 desh blend); `CombinationRecipes.java:51` (cinnabar -> sulfur + 100 mB mercury); `AnvilRecipes.java:65` (an iron or lead anvil + 10 desh ingots -> desh anvil); `ModBlocks.java:2262` and `NTMAnvil.java:44` (the desh anvil is `TIER_OIL` = 3). The selection packet follows NEO's `MachineAssemblyMachineBlockEntity.receiveControl` (migration/GOAL11C.md D2: unknown names and pooled recipes without their blueprint are ignored), without its progress reset, because the original only stores the name.

## Production code under test

Recipe world: the Goal 11B recipe world (the Goal 3C loader world, real Gson 2.10.1 from the Gradle cache) with the production `SerializableRecipe`, `GenericRecipes`, `GenericRecipe`, `AssemblyMachineRecipes` and `ChemicalPlantRecipes`, and `AssemblyMachineRecipes.java` and `ChemicalPlantRecipes.java` from the post-Goal 11B snapshot `build/migration/goal11c/base-g11b/java`, moved to the package `goal11c.base` (a second compiled table in the same world: every recipe is compared through the production writer).

Shredder world: the Goal 4 shredder world (`goal4_recipe_regression/stubs.py`, real Gson) with the production `SerializableRecipe`, `GenericRecipes`, `GenericRecipe` and `ShredderRecipes`, and `ShredderRecipes.java` from base-g11b moved to `goal11c.base`; the production loader reads and writes a scratch config directory in the run folder.

Machine world: everything the Goal 11B machine world compiles (the Goal 10C energy, fluid and heat networks, pipes, barrels, the combination oven and `CombinationRecipes`, `MachineBaseBlockEntity`, `UpgradeManagerNT`, `AnvilRecipes`, the Goal 11A derrick and burner, the Goal 11B refinery and tank), plus `ModuleMachineBase`, `ModuleMachineChemicalPlant`, `MachineChemicalPlantBlockEntity`, `MachineChemicalPlantMenu`, `SlotCraftingOutput` (the menu's output slots refuse placement, as in the game; the earlier worlds used a stand-in that accepted it), `ChemicalPlantRecipes`, `BlueprintsItem` and `AnvilSmithingRecipe`.

Not compiled: the chemical plant block, screen, renderer and JEI handler, the assembler (its own suites run unchanged; section 2t compares `ModuleMachineBase`, `ModuleMachineAssembler`, `MachineAssemblyMachineBlockEntity` and `MachineAssemblyMachineMenu` byte for byte with base-g11b), the language provider and the anvil block and menu.
