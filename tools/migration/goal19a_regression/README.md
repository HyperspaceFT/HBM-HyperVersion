# Goal19A corroded barrel verification

Covers Goal19A-2 items 2 (corroded barrel) and 4 (gravel_obsidian explosion resistance). Run from the NEO repository with the existing Python 3 and JDK 21:

- `python -B -X utf8 tools/migration/verify_goal19a_barrel.py`

Output goes to a unique `build/migration/goal19a/barrel/<run-id>/` with `report.json`, `compile.log`, `barrel.log` and one directory per mutation. The real NeoForge sources cache (`build/moddev/artifacts/neoforge-21.1.228-sources.jar`) is required: before anything is compiled, the verifier locates each Minecraft/NeoForge body the declared services follow and records its file and lines (`engine_contracts`), and resolves the NTM sources the scenarios rely on (`ntm_anchors`).

Compiled whole: the production `BarrelBlock`, `BarrelBlockEntity`, `FluidTrait` (release dispatch), `FluidTraitSimple`, `FT_Corrosive`, `FT_Polluting`, `FT_VentRadiation`, `IPersistentNBT`, `IPersistentInfoProvider`, `IMultiBlock`, `IMetaItem`, `BlockItemBase` and `BlastInfoBlockItem`, plus the Goal 7B production list (`MachineBaseBlockEntity`, `FluidTank`, `FluidContainerRegistry`, fluid network). `FluidType` is a stand-in with the production `addTraits`/`hasTrait`/`getTrait`/`isHot`/`isCorrosive`/`isHighlyCorrosive`/`isAntimatter` bodies. The barrel and gravel_obsidian rows of `NtmBlocks`, the `BARREL` block entity type's valid blocks and the traits of the fixture fluids are parsed from production and recorded under `parsed_production_facts`.

Declared services (`stubs.py`): per-position states and block entities following `LevelChunk.setBlockState`/`getBlockEntity(IMMEDIATE)`, `Level.destroyBlock`/`removeBlock`, `BlockBehaviour.onRemove`, `IBlockExtension.onBlockExploded`, `BlockEntity` state validation against `BlockEntityType.isValid`, `Containers.dropContents`, recorded drops, pollution and radiation, and a `RandomSource` that records every `nextInt` bound and is scripted per bound. Player breaking and the vanilla and NTM explosions are orchestrated by the fixture in the cited order. No chunk save/load, neighbour updates, client sync, item entities, events or gamerules.

Scenarios: registration and block entity validity (including a pre-19A corroded barrel that gains its block entity on the first `getBlockEntity`), no GUI, leak (scripted 1-in-3 rolls, one 1 mB SPILL release per leak reaching every trait, the local zero bound, no roll when empty, and the rate over 30,000 seeded ticks), self-destruct, steel to corroded under nitric acid (including no stale sync from the replaced block entity), sulfuric acid unchanged, plastic and tcalloy unchanged, corroded removal by player, explosion and `destroyBlock(true)`, the persistent item round trip at 16,000 mB, tooltips, gravel_obsidian resistance on the block, blast-info tooltip and state paths, and the comparator. Each of the seventeen mutations (reverts of this batch: capacity, leak, self-destruct body, slot drops, replacement body, fill and type copy, the removed-block-entity sync guard, block entity type and creation, the `FT_Corrosive` threshold and `FluidType.isHighlyCorrosive`, the corroded loot, explosion and break-loot guards, the old tooltip lines, gravel resistance) must compile and then fail its named scenario with the expected assertion. None of this is game, save, GUI, multiplayer or dedicated-server acceptance.
