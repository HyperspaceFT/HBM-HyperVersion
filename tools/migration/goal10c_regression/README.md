# Goal 10C isolated heating oven and electric furnace regression

Run `python -B -X utf8 tools/migration/verify_goal10c.py` with the existing Python and JDK 21. The script finds the JDK through `JAVA_HOME`, then `C:\Program Files\Java\jdk-21`, then the `PATH`. Each run writes its commands, compiler output and assertions to a distinct `build/migration/goal10c/regression/<id>/result.log`, prints the checks per section, and refuses to run if any stand-in would shadow a production source it compiles. javac receives its file list through an argument file in the run folder.

A failed assertion is printed as `AssertionError in <section> ...`; the remaining sections still run, and the run fails at the end if any section failed. Passed checks are counted, failed ones are not. Section 10 is a text check run by `verify_goal10c.py` itself and reports the same way.

`python -B -X utf8 tools/migration/goal10c_mutation_check.py` reverts or breaks 24 Goal 10C decisions one at a time in a temporary copy of `src/main/java` under `build/migration/goal10c` and reruns the regression (log: `build/migration/goal10c/mutation_check.log`). The unmutated baseline must pass first. A mutation counts as detected only when the regression reports an `AssertionError`; a mutation that does not compile or only raises another exception is reported as an error. The source tree is hashed before and after; the check fails if it changed. `--source DIR` mutates another source root and `--log FILE` writes elsewhere.

`python -B -X utf8 tools/migration/verify_goal10c_resources.py [--source-only]` checks the six imported textures against the original at `608fec4` (working file and `git show`) and `migration/goal10c-resource-ownership.json`, the generated tree against `build/migration/goal10c/stamp-before-g10c.json` (3843 -> 3850 files: exactly the 7 furnace files added, `en_us.json` and the pickaxe tag modified, nothing removed), that the current stamp's generation inputs match the sources and differ from the pre-Goal 10C stamp in exactly the 25 Goal 10C inputs (18 Java sources, `zh_cn.json`, 6 textures), the English and Chinese deltas (exactly the two new keys, 2114 and 2006 keys; the pre-Goal 10C bytes are read from the Goal 10B release JAR after checking them against the stamp), the pickaxe tag delta and the `zh_cn-map.json` entries. Full mode also compares the built JAR's entries with the generated files, textures, `zh_cn.json` and the new classes, and writes `build/migration/goal10c/generated-check.json` for `package_goal10c.py`, which keeps the JAR as `build/migration/releases/goal10c/hbmsntm-198A-goal10c.jar` and explains every entry of the delta to the Goal 10B release. After Goal 11A (`migration/GOAL11A.md`) section 1 also requires the two fluid burner entries exactly after the recycling entry (one more check), and `verify_goal10c_resources.py` runs its unchanged checks against the post-Goal 10C state (the pre-Goal 11A stamp `build/migration/goal11a/stamp-before-g11a.json`, the Goal 10C release JAR, and commit `8a209c35` for the inputs Goal 11A changes), then checks that post-Goal 10C -> now is exactly the Goal 11A set. After Goal 11B (`migration/GOAL11B.md`) the inputs Goal 11B changes that Goal 11A did not are read from the git-free snapshot `build/migration/goal11b/base-g11a/`, the Goal 11A delta is taken against the post-Goal 11A state (the pre-Goal 11B stamp `build/migration/goal11b/stamp-before-g11b.json` and the Goal 11A release's `en_us.json`), and `goal11b_delta()` checks that post-Goal 11A -> now is exactly the Goal 11B set (2 more checks). After Goal 11C (`migration/GOAL11C.md`) the inputs Goal 11C changes that Goal 11A and 11B did not are read from the git-free snapshot `build/migration/goal11c/base-g11b/`, `goal11b_delta()` compares the post-Goal 11B state (the pre-Goal 11C stamp `build/migration/goal11c/stamp-before-g11c.json`) instead of the current one, and `goal11c_delta()` from `verify_goal11c_resources.py` checks that post-Goal 11B -> now is exactly the Goal 11C set (3 more checks). ## Recorded differences and observations

- Experience: as the original `SlotSmelting` (nothing for 0; below 1 per item the whole part always and the fraction as a chance; `count` when the recipe's experience is 1 or more, where Minecraft 1.21's furnace would pay the full value). Experience is looked up by the result item (first smelting recipe), as upstream.
- Stack limit: NEO keeps `output + result <= min(max stack, 64)`; the original only checked for one free spot, so a 2-item result could overflow.
- One block with `LIT` instead of the original's `_off`/`_on` blocks; the block entity and its contents survive the switch.
- The original LIT rule is kept: with no buffer left after a tick (exactly 50 HE/t), the furnace is unlit on each completion tick.
- NEO also syncs `consumption` and clamps `power`/`progress` on load.
- Observation (not changed): `HeaterOvenBlock.onRemove` calls `destroyHeater` after the state is already air, so `findCore` returns null there and the oven-wide clear only runs from `playerWillDestroy`; removal without a player relies on the `DummyableBlock` chain and the orphan checks of neighbour updates (section 2 shows that clears exactly the one oven in this model).
